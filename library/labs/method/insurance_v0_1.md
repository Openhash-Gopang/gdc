# 보험(정액 보험료·실손 보상) 상품 명세 v0.1 (2026-10-03, P3b)

GDC 필드테스트의 보험 상품 규칙이다. **시뮬레이션용 명세**이며 서버에는 아직 없다. 이 문서의 값은 모두 **GDC 설계값**이고
외부 상품의 약관·요율에서 가져온 참고값이 아니다. 한도 명세([limits_v0_1.md](limits_v0_1.md))와 같은 면책이 적용된다 — 상용 금융 서비스가 아니고,
보험업 인허가를 대체하지 않는다. 금액 단위는 GDC(₮), 1₮ = KRW 1,000. 보험사고는 실제 사고가 아니라 **시나리오로 주어진 손실 금액**이다.

## 0. 현재 승인 범위와의 관계 (먼저 읽을 것)

- GDC에는 보험 금고·보험금 재원이 아직 없다. **이 명세는 보험금을 실제 잔액으로 지급하지 않는다.** 보험료 수취·보험금 지급·준비금은 서버에 올리기 전에 재원을 먼저 정해야 한다(미결정). 이 명세는 그 결정을 대신하지 않는다.
- 보험료 납입은 사용자 → 보험금고로 가는 이체이므로 서버에 올리면 **납입마다 이체 한도(limits_v0_1 §2)를 받는다.** 최대 월 보험료는 ₮33.34(§3)라 1회 한도에는 걸리지 않지만 1일 유출 한도에는 다른 유출과 합산된다.
- 보험금 지급은 들어오는 거래라 한도 대상이 아니다.

## 1. 계약 입력

| 필드 | 값 | 설명 |
|------|----|------|
| `coverageAmount` | 100 이상 10000 이하, 100의 배수인 정수 (₮) | 보상 한도(계약 기간 전체의 누적 상한) |
| `termMonths` | 6 또는 12 | 계약 기간(개월) |
| `riskClass` | `"A"` `"B"` `"C"` | 위험 등급. 연 보험료율이 다르다(§3). 등급은 입력으로 받는다(신용평가 등급과 연결하지 않는다) |
| `outcomes` | 배열, 원소는 `"paid"` 또는 `"missed"` | 1회차부터 차례로, 각 달의 보험료 납입 결과. `outcomes[k]`는 1부터 센 k번째 달이다 |
| `claims` | 선택, 배열 | 사고 목록. 원소는 `{ "month": 정수, "loss": 정수 }`. 없거나 `null`이면 빈 배열 |
| `cancelAt` | 선택, 정수 1 이상 | 해당 달 처리가 끝난 **직후** 사용자가 해지하는 시점. 없거나 `null`이면 해지 없음 |

"정수"는 값이 정수이면 된다(JSON의 `500.0`은 정수 500). 불리언·문자열은 정수가 아니다. NaN·무한대도 정수가 아니다. 문자열 값(`riskClass`, `outcomes` 원소)은 대소문자까지 정확히 같아야 한다(`"a"`는 `CLASS_INVALID`). 사고 원소에 `month`·`loss` 외의 키가 더 있어도 무시한다. `claims`와 `cancelAt`만 생략할 수 있고, 다른 필드(`coverageAmount` `termMonths` `riskClass` `outcomes`)가 없거나 `null`이면 그 필드의 오류 코드를 돌려준다.

입력이 아래 조건을 어기면 계산하지 않고 오류 코드를 돌려준다. 검사 순서는 `coverageAmount` → `termMonths` → `riskClass` → `outcomes` → `claims` → `cancelAt`.

| 오류 코드 | 조건 |
|-----------|------|
| `COVERAGE_INVALID` | `coverageAmount`가 정수가 아니거나 범위 밖이거나 100의 배수가 아님 |
| `TERM_INVALID` | `termMonths`가 6, 12가 아님 |
| `CLASS_INVALID` | `riskClass`가 `A`/`B`/`C`가 아님 |
| `OUTCOMES_INVALID` | `outcomes`가 배열이 아니거나, 원소가 `paid`/`missed`가 아니거나, 길이가 `termMonths`보다 큼 |
| `CLAIMS_INVALID` | `claims`가 (없음·null이 아니면서) 배열이 아니거나, 원소가 객체가 아니거나 `month`·`loss` 키가 없거나, 원소의 `month`가 정수가 아니거나 1 미만이거나 `outcomes` 길이 초과이거나, `loss`가 1 미만이거나 정수가 아니거나, `month`가 앞 원소보다 작음(같은 달 여러 건은 허용, 배열 순서가 처리 순서) |
| `CANCEL_INVALID` | `cancelAt`이 정수가 아니거나 1 미만이거나 `termMonths` 초과이거나 `outcomes` 길이보다 큼 |

사고의 `month` 상한은 `termMonths`가 아니라 `outcomes`의 길이이므로, `outcomes`가 비어 있는데 사고가 하나라도 있으면 `CLAIMS_INVALID`다. `claims`의 형식 검사는 계약이 중간에 끝나 읽지 않게 되는 뒷 달의 사고까지 포함해 배열 전체에 적용한다.

## 2. 달의 진행

달 번호 k는 1부터 시작한다. 달 k를 처리할 때 순서는 다음과 같다.

1. **보험료**: `outcomes[k]`가 `paid`이면 그 달 보험료가 납입된 것이고(납입한 달 수에 1을 더한다), `missed`이면 납입되지 않은 것이다. 후납·선납은 없다.
2. **사고 처리**: `month == k`인 사고를 배열 순서대로 처리한다(§3). 사고 결과는 `claimResults`에 사고 입력 순서대로 기록된다.
3. **종료 판정**(아래 순서로 첫 번째로 해당하는 것):
   - (가) `outcomes[k]`와 `outcomes[k-1]`이 모두 `missed`(2회 **연속** 미납)이면 이 달 끝에 **실효**(`lapsed`). k = 1 이면 직전 달이 없으므로 연속 미납이 아니다.
   - (나) 이 달의 사고 처리를 마친 뒤 **잔여 보상 한도가 0**이면 `exhausted`(소진). 보상 한도는 처음에 100 이상이라 지급이 있어야만 0이 된다.
   - (다) `cancelAt == k`이고 k < `termMonths`이면 `cancelled`.
   - (라) k == `termMonths`이면 `matured`(만기).
   - 어디에도 해당하지 않으면 다음 달로 간다. `outcomes`가 끝났는데 종료되지 않았으면 상태는 `active`다.
4. 종료된 계약은 이후 달의 `outcomes`·사고를 읽지 않는다(형식 검사는 §1대로 배열 전체에 이미 적용됐다). 계약이 `cancelAt`보다 앞서 실효·소진으로 끝나면 `cancelAt`은 무시한다(오류가 아니다). 실효되는 달에도 §2의 순서대로 그 달의 사고를 먼저 처리한다(그 달은 미납이므로 `UNPAID`). 종료 뒤의 달에 있는 사고는 `claimResults`에 나타나지 않는다. 만기 달에 `cancelAt == termMonths`이면 만기로 본다.

보험료 환급은 어느 종료 상태에서도 없다. 만기 환급금·해약환급금은 없다(소멸성).

## 3. 보험료와 보상

**월 보험료**: 연 보험료율은 등급별로 A 100bp(1.00%), B 200bp, C 400bp (GDC 설계값). 월 보험료(1/100 ₮ 단위, 센트)는 `ceil(coverageAmount × rateBp / 1200)`이다 (올림). 예: ₮1,000 보상 한도, A 등급 → ceil(1000×100/1200) = ceil(83.33) = 84센트 = ₮0.84. 계약 총 보험료 = 월 보험료 × 납입한 달 수.

**자기부담금**: `coverageAmount / 10`(보상 한도의 10%, 정수 ₮ — 한도가 100의 배수이므로 항상 정수).

**사고 한 건의 처리** (사고 `{month, loss}`, 처리 시점의 잔여 보상 한도 R. 최초 R = `coverageAmount`). 아래 순서로 **첫 번째로 해당하는 것**을 결과로 한다. `payout`은 ₮ 정수.

| 순서 | 조건 | `reason` | `payout` |
|------|------|----------|----------|
| 1 | `month == 1` (면책 기간: 첫 달 사고는 보상하지 않는다) | `WAITING` | 0 |
| 2 | 그 달 `outcomes[month]`가 `missed` | `UNPAID` | 0 |
| 3 | R == 0 (같은 달 앞선 사고로 한도가 소진됨) | `EXHAUSTED` | 0 |
| 4 | `loss ≤ 자기부담금` | `BELOW_DEDUCTIBLE` | 0 |
| 5 | `loss − 자기부담금 ≤ R` | `PAID` | `loss − 자기부담금` |
| 6 | 그 밖(`loss − 자기부담금 > R`) | `PARTIAL` | R |

지급이 있으면 R에서 `payout`을 뺀다. 면책 기간(순서 1)이 미납(순서 2)보다 앞선다.

## 4. 출력

| 필드 | 설명 |
|------|------|
| `status` | `matured` / `cancelled` / `lapsed` / `exhausted` / `active` |
| `endMonth` | 계약이 끝난 달 번호 (`active`면 처리한 마지막 달 번호, `outcomes`가 비어 있으면 0) |
| `paidCount` | 보험료를 납입한 달의 수 |
| `premiumTotal` | 낸 보험료 합계(₮, JSON 숫자로 소수 둘째 자리까지) = 월 보험료(센트) × `paidCount` ÷ 100 |
| `claimResults` | `[{ month, loss, payout, reason }]` — 처리된 사고, 입력 순서 |
| `totalPayout` | 보험금 합계(₮ 정수) |
| `remainingCoverage` | 잔여 보상 한도 = `coverageAmount − totalPayout` |

## 5. 알려진 한계

1. 값(요율 100/200/400bp, 자기부담금 10%, 면책 기간 1개월, 연속 2회 미납 실효, 한도 100~10,000₮)은 모두 GDC 설계값이며 근거 자료가 없다. 위험 등급별 요율은 통계에 기반하지 않는다.
2. 보험금 재원(준비금)과 보험료 수입의 회계 처리가 정해지지 않았다(§0). 서버에 올리지 않는다.
3. 사고의 진위·원인·보험사고 해당 여부(약관 면책)는 판정하지 않는다. 입력된 손실 금액을 사실로 받는다. 이것이 실제 보험의 핵심 난제(도덕적 해이, 사기)이며 이 명세는 다루지 않는다.
4. 한도로 보험료 납입이 거절된 달의 처리는 서버 이식 때 정한다(적금 명세 §6과 같은 미결정). 여기서는 `missed`로 이미 결정된 입력을 받는다.
5. 납입일·유예기간·부활·휴일·시간대는 다루지 않는다. 달 번호만 있다.
6. 서버 스키마와 엔드포인트가 없다. 시뮬레이터(`js/gdc-insurance.js`)와 라운드 5 시나리오로만 검증된다.
7. 검증 이력: 라운드 5(`rounds/r05`), 독립 검수 `rounds/r05-check`, 재검토 `rounds/r05-final` — 같은 제작사의 다른 모델이 한 검수이며 제3자 검증은 아니다.
