# GDC 방법론 — 갱신 기록 (CHANGELOG)

`gdc_credit_v*.md` (신용평가), `gdc_valuation_v*.md` (기업가치 평가), `gdc_check_v*.md` (독립 검수)
의 버전별 변경 내용을 최신순으로 기록한다. klaw의 `CHANGELOG_klaw.md` 와 같은 형식이다.
버전 표기는 `major.minor[.patch]` 이며, 각 버전의 원문 전체는 저장소 루트의 해당 파일에 둔다.

## limits v0.1 — 서버 반영 (2026-10-03)

**내용**: 값·검사 순서·결과 코드는 바꾸지 않고, 서버 반영 상태와 서버 구현이 택한 방식을 명세에 기록했다.
**반영**: 대출 신청 한도 — hondi #514. 테스터 계정의 이체·예치 한도 — hondi #515 (`tx.items`가 비고 보내는 계정이 테스터일 때만 적용).
**서버 구현의 차이**: 기존 대출의 연 상환액을 호출자 입력이 아니라 서버가 활성 대출에서 12개월 가정으로 계산한다.
**미결정**: 대출 상환이 이체 한도를 받는 문제(명세 §7).

## limits v0.1 (2026-10-03, P1)

**파일**: [`limits_v0_1.md`](limits_v0_1.md) · 기준 구현 `js/gdc-limits.js`
**배경**: 실제 GDC 잔액이 움직이는 거래를 필드테스터에게 열기로 한 결정(2026-10-03)에 따라 한도 규칙이 필요해졌다.
**내용**: 1회 이체 ₮1,000, 1일 유출 ₮2,000, 신규 수취인 ₮100, 대출 1건 ₮3,000 / 잔액 합계 ₮5,000 /
순자산 70% / DSR 40%(스트레스 가산 1.5%p, 만기 12개월 가정). 검사 순서·경계 규칙·서버 이식 요건 포함.
**주의**: 값 대부분이 근거가 약한 GDC 설계값이다. (P1 시점에는 어디에서도 강제되지 않았다 — 위 "서버 반영" 항목 참조.) 라운드 1(R01) 32건은
기준 구현과의 일치만 확인한 것이다.
