# r06-check 대조 결과 (파이프라인 2단계 — 독립 검수 vs 실행)

검수자는 방법론·명세 문서(credit: gdc_credit_v1_0.md, savings: savings_v0_1.md, valuation: gdc_valuation_v0_1.md, insurance: insurance_v0_1.md, securities: securities_v0_1.md와 그것이 인용하는 신용평가 문서)와 시나리오 입력만 받았고 expected 값과 구현 코드는 보지 못했다.
**일치 71 / 71**

## 검수자가 짚은 문서의 모호한 곳

1. 오류 검사는 표의 행 순서(필드 단위)대로 첫 실패를 반환한다고 해석함 (예: payoutBp 9000 + depositors 문자열 → PAYOUT_INVALID). 한 필드 내 원소 검사 순서는 같은 코드라 결과 무관.
2. positions/depositors 생략·null이면 shares=[] , W=0 → undistributedCents = distributable×100 으로 계산.
3. id '비어 있지 않은 문자열': 공백만 있는 문자열(예: ' ')도 비어 있지 않은 것으로 봄(명세 침묵; 시나리오에는 없음).
4. 정수형 실수(1000.0)는 출력에서 정수로 정규화함. JSON 지수표기/매우 큰 수(정밀도 손실 float)의 처리 기준은 명세가 침묵.
5. principal=0이고 종목이 있으면 ISSUER_CONCENTRATION과 INVESTED_CAP이 둘 다 위반(cost≥1이므로 식으로도 동일)으로 둘 다 기록.
6. net이 음수여도 출력 net은 음수 그대로, poolCents는 distributable(≥0) 기준이라 floor 음수 처리 문제 없음.
7. 최상위 inputs가 객체가 아닌 경우의 처리는 명세가 침묵(시나리오에는 없음).
