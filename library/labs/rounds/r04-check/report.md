검수자는 방법론·명세 문서(credit: gdc_credit_v1_0.md, savings: savings_v0_1.md, valuation: gdc_valuation_v0_1.md와 그것이 인용하는 신용평가 문서)와 시나리오 입력만 받았고 expected 값과 구현 코드는 보지 못했다.

## 검수자가 짚은 문서의 모호한 곳

1. tester 값이 true/false/생략이 아닌 경우(예: 문자열 "true", 숫자 1, null)는 문서가 '불리언 tester'·'true일 때만'이라고만 함 -> 엄격히 불리언 true만 테스터로 가정 (이번 입력엔 해당 사례 없음)
2. fs 객체 자체가 없거나 null/비객체인 경우 미정의 -> 없거나 null이면 모든 fs 필드 0, 비객체면 INPUT_INVALID로 가정 (해당 사례 없음)
3. '그 밖의 비숫자 값'에 배열·객체가 포함되는지 명시 없음 -> INPUT_INVALID로 가정 (해당 사례 없음)
4. 정수값 실수 판정 기준: 1000.0 외에 1e3 같은 지수 표기, 2^53 초과 실수 등은 언급 없음 -> JSON 리터럴을 Decimal로 정확히 읽어 값이 정수이면 정수로 봄
5. inputs.json에서 bsCash는 fs 밖 최상위, 나머지는 fs 안에 있음 -> fs 안의 bsCash나 최상위의 다른 필드는 무시한다고 가정 (해당 사례 없음)
6. 신용평가 v1.0 §1은 bsCash·bs_ap·bs_equity·pl_revenue·cf_op의 누락/비숫자, 음수 bs_debt 결과를 미정의로 두나, 가치평가 v0.1 §1(누락·null=0, 음수 불가 항목은 INPUT_INVALID)이 우선한다고 보고 적용함
7. 정의되지 않은 추가 필드(bs_inventory 등)는 유효성 검사 대상이 아니라고 가정 (해당 사례 없음)
