# r07-final — 재검토 (파이프라인 3단계)

검수 결과와 대조 보고서: [`../r07-check/report.md`](../r07-check/report.md). 지침: `gdc_check_v1_0.md` §4 (적금 v0.2 명세 `savings_v0_2.md`에도 같은 절차를 적용).

## 최종 결과

**적금 v0.2(수익 연동 이자) 48건: 구현 48 / 48 통과, 독립 검수와 48 / 48 일치.**
검수자는 같은 제작사의 다른 모델(Opus 하위 세션)이며 완전한 독립 검증이 아니다.
expected는 `rounds/r07/gen_scenarios.py`의 참조 계산이 실행 전에 냈다. 참조 계산과 구현은 같은 사람이 같은 명세를 읽고 만들었으므로 둘의 일치는 독립 증거가 아니다 — 독립 증거는 검수자의 계산이다.

## 검수자가 짚은 것 (1회, 48건)

| # | 지적 | 판단 | 조치 |
|---|------|------|------|
| 1 | k는 1부터 세는 달 번호이고 배열 인덱스는 k−1 | 반박 | §2가 이미 v0.1과 같은 규약을 쓰고 §1에 "달 k의 정산"이라 적었다. 변경 없음 |
| 2 | `settlements` 원소에 키가 없을 때 | 수용 | §1에 `SETTLEMENTS_INVALID`로 명시 (시나리오 sav7-042가 이미 포함) |
| 3 | `outcomes`가 빈 배열이면 유효한지 | 수용 | §1에 "빈 배열이면 `settlements`도 비어야 하며 유효" 명시 (시나리오 sav7-010) |
| 4 | `active`의 `accruedCents` | 수용 | §1에 "그때까지의 누적값" 명시 |
| 5 | 정수 표기와 실수 표기의 구분 | 반박 | 값이 정수이면 정수로 본다는 규칙(§1)이 이미 있고, JSON 숫자는 둘을 구분하지 않는다 |
| 6 | `1000.0`을 정수로 | 반박 | 위와 같다 (§1) |
| 7 | `CANCEL_INVALID`의 길이 기준 | 반박 | §1에 "`outcomes` 길이보다 큼"이라고 적혀 있다. v0.1과 같다 |
| 8 | B_k = 0, `totalBalance` = 0 의 일관성 | 반박 | §2-3이 "B_k = 0 이면 이자 0"이라 적고, 불일치는 B_k > `totalBalance`일 때만이다 |
| 9 | `poolCents`에 상한이 없어 비현실적 재원도 그대로 계산 | 수용(한계로 명시) | §5-4에 "상한·관계 제약 없음, 정산이 증권 운용 규칙의 결과라는 가정에 의존" 추가 |

2·3·4·9번의 명확화는 §1·§5에 한 문장씩 보탠 것이며, **새 검수자가 아니라 같은 검수자의 스크립트를 문서 수정 후 다시 돌려** 결과가 바뀌지 않음(48건 동일)을 확인했다 — 독립성이 한 단계 약하다.

## 이 라운드로 알 수 없는 것

- 중도해지 이자 50%가 수익 연동형에 맞는지 (확정 이율형 때의 값을 가져온 것, 시험하지 않았다).
- 정산이 증권 운용 명세 §3의 결과와 실제로 일치하는지 — 이 명세는 정산을 입력으로 받을 뿐이다. 두 명세를 이어서 돌리는 통합 시나리오는 아직 없다.
- 해지로 포기한 이자의 귀속 (명세 §5-3).
