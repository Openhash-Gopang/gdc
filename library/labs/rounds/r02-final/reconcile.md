# r02-final — 재검토 (파이프라인 3단계)

검수 결과 전문과 대조 보고서: [`../r02-check/report.md`](../r02-check/report.md). 지침: `gdc_check_v1_0.md` §4.

## 최종 결과

**신용평가 57건: 구현 57 / 57 통과, 독립 검수와 57 / 57 일치** (아래 문서 수정과 생성기 수정 반영 후).
권위 있는 결과는 이 디렉터리가 아니라 문서 수정 후 다시 한 실행 [`../r02/results.md`](../r02/results.md)와 2차 검수
[`../r02-check/report.md`](../r02-check/report.md)다. 이 파일은 그 사이에 무엇을 받아들이고 무엇을 받아들이지 않았는지 기록한다.

## 1차 검수 (명확화 전 문서) — 검수자가 짚은 것

| # | 지적 | 판단 | 조치 |
|---|------|------|------|
| 1 | 표시 점수의 동점 반올림(71.25 → 71.3 or 71.2) 규칙이 없다 | 수용 | 방법론 §4에 "동점은 올린다" 명시 |
| 2 | 연 금리 단위가 표(%)와 구현(소수)이 다르다 | 수용 | §4 표에 "구현 값(소수)" 열 추가 |
| 3 | 부채비율 표에서 `bs_equity` > 0 조건이 첫 행에만 있다 | 수용 | §2·§3에 조건 범위 명시 |
| 4 | §2(분모 ≤ 0이면 판단 불가)와 §3(순자산 부호별 점수)의 우선순위 | 수용 | §2에 "§3 규칙이 우선" 명시 |
| 5 | 테스터 여부를 입력 `tester`로 대체 | 반박 아님, 기록 | 문서 정의(레코드 존재)와 같은 의미로 취급. 변경 없음 |
| 6 | `pl_*` 기간이 정해지지 않았다 | 이미 §7-5에 알려진 한계 | 변경 없음 |

**검수가 드러낸 작성 측 결함**: 시나리오 생성기가 expected 점수를 파이썬 기본 반올림(짝수 쪽)으로 만들어, 총점 71.25인
시나리오에 71.2를 적었다. 구현은 71.3을 낸다. 러너의 점수 허용오차(0.1)가 이 차이를 가리고 있었다.
조치: 생성기를 올림 반올림으로 고치고, 러너 허용오차를 0.001로 줄였다. R01의 expected는 반올림 전 총점(예: 61.25)이라 러너가
방법론 §4 규칙으로 반올림해 비교하게 했고, R01은 이후에도 32/32다. 이 결함은 구현이 아니라 시험 도구에 있었다.

## 2차 검수 (명확화한 문서, 새 검수자) — 검수자가 짚은 것

| # | 지적 | 판단 | 조치 |
|---|------|------|------|
| 1 | 순자산 0이면서 부채 < 0인 입력은 표가 정의하지 않는다 | 수용 | §1에 금액 항목은 0 이상(`bs_equity`·`cf_op` 제외)이고 음수 `bs_debt`는 정의하지 않는다고 명시 |
| 2 | 경계 포함 방향 표기가 일관된지 확인 | 충돌 없음 | 변경 없음 |
| 3 | 게시된 등급표(gdc.hondi.net)와의 일치는 이 두 파일만으로 확인 불가 | 맞음, 이 절차의 범위 밖 | 변경 없음. 방법론 §4가 요구하는 사항으로 남겨 둠 |
| 4 | 표시 점수의 자료형 | 구현이 number를 반환 | 변경 없음 |
| 5 | `pl_*` 기간 | §7-5 | 변경 없음 |

2차 검수의 지적 1은 문서 수정 후 한 번 더 검수하지 않았다(한 문장 추가이며 시나리오에 해당 입력이 없다).

## 시험의 효력

v0 구현(방법론 변경 전 코드)으로 R02를 돌리면 57건 중 53건 통과, 부채비율 변경 시나리오 4건(cred2-001, 002, 003, 045)이
불일치한다. 따라서 R02는 v1.0 변경을 실제로 잡아낸다.
