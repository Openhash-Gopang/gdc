# GDC 필드테스트 — 방법론·시나리오·라운드

klaw의 `library/benchmark/` 에 대응하는 폴더다. 은행(예금·적금·대출), 보험, 증권, 디지털 화폐
기능을 시나리오로 시험하고, 신용평가·기업가치 평가 방법론을 라운드마다 갱신·검증하는
절차를 기록한다.

**상태 (2026-10-03, P0)**: 골격만 있다. 이 폴더의 모든 수치·결과는 아직 없다.

**면책**: GDC는 고팡 플랫폼 안의 결제·저축·대출 단위이며, 이 테스트는 은행업·보험업·금융투자업
등 인허가를 대체하지 않는다. 여기 수록되는 데이터는 자체 실험 결과이며 제3자 검증을 거치지
않았다. 특허 출원 명세서의 처리 속도·정확도 수치는 검증되지 않은 값이므로 어디에도 옮기지 않는다
(로드맵 v1.2 §0 원칙 유지). "특허 출원" · "특허 등록" · "실제 구현"을 섞어 쓰지 않는다.

## 0. 테스트 범위와 가드 (2026-10-03 결정)

| 항목 | 결정 |
|------|------|
| 거래 범위 | 실제 GDC 잔액이 움직이는 거래까지 포함한다 (예금·적금·대출·보험료/보험금·증권 거래) |
| 대상 계정 | 현직 금융기관 종사자 필드테스터에 한정한다 (`gdc_test_*` 레코드가 있는 계정만). 일반 이용자에게 노출하지 않는다 |
| 확대 | 일반 이용자 확대는 이 결정의 범위 밖이다. 별도 법률 자문과 인허가 검토가 먼저 필요하다 |
| 표기 | 모든 상품 컬렉션은 `gdc_test_` 접두어를 쓰고, 모든 페이지에 필드테스트 안내를 둔다 |

실제 잔액이 움직이므로 P1에서 아래 요건을 코드와 테스트로 확정한 뒤에야 해당 상품을 연다.
아래는 **설계 요건**이며 현재 구현된 것이 아니다.

- 모든 거래에 ED25519 서명을 요구하고 PDV에 6하 원칙으로 기록한다.
- 계정별·거래별·일별 한도를 둔다. 한도 값은 P1에서 정한다 (미정).
- 오입력 거래는 삭제·롤백하지 않고 보정 거래로 상쇄한다 (원장 불변성).
- 테스터 allowlist(`gdc_test_*` 레코드 존재 여부)를 서버 쪽에서 검사한다. 브라우저 쪽 검사에 의존하지 않는다.
- 상품별로 "되돌릴 수 없는 거래"와 "시뮬레이션 거래"를 화면에서 구분해 표시한다.

## 1. 전체 구조

```
시나리오 매트릭스 작성(상품별)
   -> 라운드 N: 그 시점의 방법론으로 표본 밖 시나리오 실행 -> 기대 결과와 대조
   -> 오류 분석 -> 방법론 패치안 작성(같은 유형 오류 2회 이상 또는 구조적 결함일 때만 갱신)
   -> 라운드 N+1 ...
```

핵심 원칙은 klaw와 같다. **각 라운드의 결과는 그 라운드 시작 시점의 방법론으로, 아직 보지 않은
시나리오에 대해 얻는다.** 방법론을 특정 시나리오에 맞추는 과적합을 구조적으로 제한하기 위해서다.
임의 규칙 추가는 금지한다.

## 3. 알려진 한계 · 미해결 항목 (P0 시점)

1. **기존 테스트 3건이 이미 실패한다** (`node --test test/*.test.mjs` -> 36건 중 33 통과, 3 실패).
   - `activated_features.test.mjs`: "accrueInterest/applyLoan/repayLoan은 export되지 않는다",
     "evaluateCredit()는 호출 시 명시적으로 실패한다" — 이 두 테스트는 2026-07-18 LEGAL-HOLD
     상태를 단언한다. 2026-09-06 필드테스트 승인으로 코드가 바뀌었는데 테스트가 따라가지 않았다.
   - `src_gdc.test.mjs`: "calcExpectedVolatility matches README claim (<5% for stable)".
   - 실제 잔액 거래를 포함하기로 한 결정으로 가드 모델이 바뀌므로, P1에서 테스트를 현재 승인 범위에
     맞게 다시 쓴다. P0는 이 테스트들을 건드리지 않았다.
2. `README.md` §3~§4 의 모듈 트리·데이터 모델은 v1.0(Supabase) 설계 시점 기준이다.
   Supabase는 폐기됐으며 현행 데이터 모델은 `pb_migrations/` 가 기준이다.
3. 보험·증권·적금·기업가치 평가는 코드·스키마·문서가 아직 없다 (P2~P3).
